# 真实进程故障验证

目标：把异常注入扩展为真实进程终止与新进程恢复，验证磁盘 checkpoint 而不是内存对象。

代码：`local_tests/test_process_recovery.py`；子进程程序：`local_tests/helpers/crash_worker.py`。

父进程用 Popen 启动独立 Python 程序。子进程在指定边界完成持久化后，通过 stdout 输出 READY 并等待信号；父进程发送 SIGKILL，确认退出码，再启动全新进程调用 resume。每次等待有超时，finally 会清理仍存活的子进程，测试不调用模型 API。

| 故障点 | 终止时副作用数量 | 恢复路径 |
| --- | --- | --- |
| 意图已保存、执行工具前 | 0 | 人工核实未执行，提交 tool_error，不重试 |
| 等待用户批准 | 0 | 锁释放后显示结果待核实，不能跳过审批后执行 |
| 工具函数内部、写入前 | 0 | 人工核实未执行，不重试 |
| 副作用写入并 fsync、工具返回前 | 1 | 人工确认结果，不重复写入 |
| 工具结果已保存 | 1 | 自动继续模型轮次，不执行已完成工具 |
| SQLite 报告事务提交、工具返回前 | 1 | 按 operation ID 查到回执，自动继续，不再次执行 |

前五个场景还在子进程存活时探测 OS 锁，确认状态为 running 或 waiting_approval。终止后锁自动释放，恢复保留调用预算。每个场景都检查实际副作用数量和最终结果。

设置 CARDINAL_TEST_ARTIFACTS 为输出目录后，测试保存每个场景的 JSON 指标；事务报告场景还保存虚构数据 transcript。最终评测目录同时保存 pytest 输出、JUnit、源码与测试哈希、运行环境和命令。

这证明这些具体边界在本机测试中的恢复行为，不证明断电耐久性、NFS 锁、数据库损坏、Windows 原生支持或所有外部服务的恰好一次执行。运行时间是整套测试耗时，不是用户任务提速比例。
