# 实际可用性与企业试点路线

## 当前可以使用到什么程度

当前是单用户、本地运行、远端模型推理的员工助手预览版。可以导入自己的 Markdown 和邮件 JSONL，查询来源、做日报和统计、保存个人记忆、审批命令并检查对话日志。不是空壳 UI：入口复用已测试的 Agent 和工具。

适合开发者自己或在获得资料/模型服务许可后的个人试用。没有真实公司部署、用户留存、人工节时或生产 SLA 数据；课程语料和 persona 不能作为商业使用证明。

## 缺口与具体后续工作

| 层级 | 现有能力 | 企业日常使用前仍需完成 | 验收方式（计划，不是已达标数据） |
| --- | --- | --- | --- |
| 数据接入 | 手动 Markdown/JSONL 导入 | 只读 OAuth 邮箱/日历/文档连接器，增量同步与删除传播 | 撤权后不再读取；增量更新不重建全库；真实试点数据对账 |
| 权限 | 单独本地 profile、命令审批 | 多人服务需要 SSO、RBAC/文档 ACL、租户隔离 | 不同员工的检索、记忆、日志、缓存不能交叉 |
| 隐私 | key 不写 config，profile 本地保存 | 企业批准的推理服务、保留策略、敏感信息管理及加密/设备策略 | 评审供应商和数据流；完整删除及备份恢复演练 |
| 可靠性 | 有限回合、预算、超时、失败记录 | 取消/恢复任务、API 限流退避、工具幂等、持久任务状态 | 断网/进程终止/部分写入/重复提交测试 |
| 知识正确性 | 原文片段、行号、更新指针 | 明确冲突决策、更多格式与新鲜度、无答案阈值 | 留出真实问题集，人工核查证据，持续回归 |
| 记忆 | 范围/时间/来源、更正、查看和单条删除 | 语义级事实校验、删除历史日志/缓存、跨进程事务和过期策略 | 中文/否定/假设/多项目反例；完整数据生命周期测试 |
| 工具安全 | 正则、确认模式、可选 sandbox | 更强命令语义和文件边界、远端副作用授权、平台验证 | 跨平台和更多攻击语料；不能把七个场景当免疫证明 |
| 运维 | doctor、费用账本、保存会话、release 校验 | 版本升级/迁移、监控、错误聚类、受控灰度和回滚 | 升级旧 profile；恢复备份；重复安装与回滚 |
| 交互 | 同步 CLI、工具追问和审批 | 流式输出、长任务进度、交互中途消息队列 | 用户可确认当前动作；界面不把命令文本当执行成功 |

## 建议推进顺序

1. 先完成小范围单人试用：用非敏感、获授权的资料，收集任务清单、失败与耗时，不承诺自动修改业务系统。
2. 再加一个真实的只读连接器，先把同步、权限和删除做正确，避免一开始接十个系统。
3. 有数据后再决定检索/记忆算法与模型分工；比较同样的数据、模型和缓存条件，记录质量、成本与延迟。
4. 多人服务单独设计身份、权限、存储和部署，不把本地文件路径当租户隔离方案。

当前不继续模型调参。上述是后续工程路线，未以“已优化”或“已上线”对外宣传。
