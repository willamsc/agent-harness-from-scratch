# 项目介绍与面试参考

## 项目定位

Cardinal Agent：面向员工个人工作流的本地助手原型，实现 Agent Harness，并提供独立 CLI、用户资料导入、持久 profile、诊断和可验证发布。

不要写成受雇于某公司完成的生产系统，也不要虚构 DAU、真实客户、人工工时节省或 SLA。当前公司和 persona 为虚构，Enron 是公开评测语料。

## 可用的简历表述

“实现员工助手 Agent Harness，完成文本工具协议、JSON Schema 验证、审批/拒绝、上下文压缩及带来源的跨会话记忆；在 20 个公开模拟用户任务上，以程序检查与模型评审共同判定获得 18/20 成功。扩展可安装 CLI、隔离用户 profile、自有文档/邮件导入及带 SHA-256 的发布产物。”

检索专项可以补充：“实现倒排索引与 BM25，在 26,278 封公开邮件的历史本机测试上平均查询约 8.4 ms，17 个查询平均 recall@10=100%。”注明样本和测量范围；不是向量检索或其他产品的对照提速。

## 技术取舍与证据

- **框架从零构建**：模型只收发文本，自行实现协议、预算、异常恢复和事件日志。不是调用现成 Agent 框架冒称自研模型。
- **工具执行与授权分离**：参数验证、拒绝规则、用户审批、执行；失败不盲目重放，显式处理部分副作用。
- **证据检索**：倒排索引定位候选，BM25 排序；结构分块和行号便于复查，更新指针不等同于自动判定权威。
- **长期状态**：原始日志、最近交互、结构摘要、用户原话兜底；跨会话记忆有 scope/时间/来源，更正保留旧记录供历史查询。
- **数据可追溯**：成功和失败评测都保存；不同缓存条件不拿来计算虚假的成本/延迟提升。
- **产品交付**：可安装 wheel、源码 ZIP、manifest 和校验和；验证从新环境安装而非只在开发目录启动。

## 演示建议

1. 在新 profile 执行 init --demo 和离线检索，解释 demo 与公司实际数据区别。
2. 展示 import 自有 Markdown、基于来源行号问答，以及 memory/history。
3. 选择安全计算任务，展示确认模式和拒绝后适应；不要现场执行危险命令。
4. 打开评估报告，主动解释两个失败及后续边界，说明哪些指标尚无对照。

Release 可下载不代表真正具备企业部署经验。面试中应能逐段解释代码、数据流和失败原因，AI 协作开发事实不应隐藏或冒称所有实现均手写。
