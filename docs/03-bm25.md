# 实现笔记 3：BM25 关键词检索（bm25）

## 1. 本题做什么

实现一个无需 LLM 的检索器：输入字符串文档列表建立索引，再根据查询返回前 k 个 `(文档下标, 分数)`。邮件的主题和正文由调用方组合传入，检索器不负责读取档案或生成答案。第 4 题才会让模型阅读检索结果并回答问题。

题目要求使用课程的 `tokenize()`，固定 k1=1.5、b=0.75、Lucene IDF，不能使用检索库。分数误差不超过 1e-6，同分时小下标优先；无共同词的文档不返回。重复查询词只算一次。空文档仍参与文档总数及平均长度。

全邮件档案建索引少于 15 秒、平均查询少于 20 毫秒、20 万文档中仅命中 3 篇的稀有词查询少于 2 毫秒。17 个公开查询的平均 recall@10 至少为 0.90。本题全部测试为确定性测试，无须调用模型或支付 API 费用。

## 2. 原理与我们确认的方案

倒排索引和 BM25 分工不同：倒排索引是用于快速定位候选文档的数据结构，BM25 是为候选文档计算相关性分数的算法。

例如：

```python
docs = ['heron approval', 'lunch tomorrow', 'heron heron deadline']
postings = {
    'heron': [(0, 1), (2, 2)],
    'approval': [(0, 1)],
    'lunch': [(1, 1)],
    'tomorrow': [(1, 1)],
    'deadline': [(2, 1)],
}
```

每条记录是 `(文档下标, 该词在该文档的次数)`。查询 heron approval 时只需访问文档 0 和 2，不访问文档 1。

我们确认采用一个 `BM25Index` 类，保存：

| 属性 | 内容 |
| --- | --- |
| postings | 词到 `(doc_id, frequency)` 列表的映射 |
| doc_lengths | 与原列表位置一致的分词长度列表，包含零长度文档 |
| num_docs | 全部文档数 N |
| avgdl | 平均长度 |
| idf | 各词的 IDF，建索引时计算后复用 |

不保存原始正文，因为查询评分只需要这些统计。索引建好后，search 只读取统计，每次创建自己的 scores，方便并发复用。

## 3. 公式逐项解释

对每个不同的查询词 t，计算它对候选文档 d 的贡献，再相加：

```text
IDF(t) = ln(1 + (N - nt + 0.5) / (nt + 0.5))
norm(d) = 1.5 * (0.25 + 0.75 * doc_length[d] / avgdl)
contribution(t, d) = IDF(t) * frequency(t, d) * 2.5 / (frequency(t, d) + norm(d))
score(query, d) = 所有不同查询词的 contribution 之和
```

N 为全部文档数；nt 是包含这个词的文档数，即倒排列表的长度。一篇文档重复某词 100 次，nt 仍只增加 1。

- 词频越高通常越相关，但加分逐渐饱和，避免重复文本无限占优。
- 词越稀有，IDF 越高；罕见项目名一般比 meeting 更有区分力。
- 长文档更容易偶然包含词，所以使用文档长度与平均长度的比值调整。
- 使用带 +1 的 Lucene IDF，常见词也保持正值，不换成其他 BM25 变体。

## 4. 建索引流程

1. 按输入顺序 enumerate 文档，下标就是 doc_id。
2. 用课程 tokenize 分词；它将文本小写后提取 a-z 和 0-9 连续片段。
3. 记录 token 数，使用标准库 Counter 计算该篇的词频。
4. 把每个不同词的 `(doc_id, frequency)` 追加到 postings。
5. 计算 N、avgdl，再根据每个词的倒排列表长度计算 IDF。

文档正文只遍历一轮；最后遍历词表计算 IDF，不需要重新扫描语料。

## 5. 查询流程

1. k <= 0 或 avgdl 为 0 时直接返回空列表。
2. tokenize 查询，再 set 去重；额外排序词项，使浮点加法顺序稳定。
3. 只遍历查询词对应的 postings，未知词直接跳过。
4. 对每个命中文档，按公式计算该词贡献并加到本次 scores。
5. 用 `heapq.nsmallest(k, scores.items(), key=lambda pair: (-pair[1], pair[0]))` 返回前 k 项。

这里取 nsmallest 是因为使用负分数作为键：分数越高，负数越小；第二个键是 doc_id，实现同分时小下标优先。返回值仍保留正的原始 score。

设查询词对应倒排记录共 P 条，命中的不同文档为 M，常见的小 k 情况下评分约 O(P)，选取前 k 项约 O(M log k)。不会遍历全部 N 篇文档。k 大于候选数时标准库可直接排序全部候选。空查询或无匹配使 scores 为空，自然返回 []。

## 6. 完整代码

### 索引与评分

```python
"""BM25 ranking over term postings, without scanning unrelated documents."""

from collections import Counter, defaultdict
import heapq
import math

from cardinal_agent.tokenizer import tokenize


class BM25Index:
    """Build once, then share read-only statistics across independent searches."""

    K1 = 1.5
    B = 0.75

    def __init__(self, docs: list[str]):
        self.postings: dict[str, list[tuple[int, int]]] = {}
        self.doc_lengths: list[int] = []
        for doc_id, text in enumerate(docs):
            tokens = tokenize(text)
            self.doc_lengths.append(len(tokens))
            for term, frequency in Counter(tokens).items():
                self.postings.setdefault(term, []).append((doc_id, frequency))

        self.num_docs = len(self.doc_lengths)
        self.avgdl = sum(self.doc_lengths) / self.num_docs if self.num_docs else 0.0
        self.idf = {
            term: math.log(1 + (self.num_docs - len(entries) + 0.5) / (len(entries) + 0.5))
            for term, entries in self.postings.items()
        }

    def search(self, query: str, k: int) -> list[tuple[int, float]]:
        if k <= 0 or self.avgdl == 0:
            return []

        scores: dict[int, float] = defaultdict(float)
        # Stable term order also makes floating-point accumulation reproducible.
        for term in sorted(set(tokenize(query))):
            entries = self.postings.get(term)
            if not entries:
                continue
            idf = self.idf[term]
            for doc_id, frequency in entries:
                norm = self.K1 * (1 - self.B + self.B * self.doc_lengths[doc_id] / self.avgdl)
                scores[doc_id] += idf * frequency * (self.K1 + 1) / (frequency + norm)

        return heapq.nsmallest(k, scores.items(), key=lambda pair: (-pair[1], pair[0]))

```

### Adapter 接入

```python
def run_bm25_build(docs: list[str]) -> Any:
    """Problem (bm25).

    Build and return a BM25 index over ``docs``. Document ids are list
    positions. Tokenize with ``cardinal_agent.tokenizer.tokenize``. A document
    with no tokens is still a document (it counts in N and in the average
    length). The returned object is opaque to the tests; they only pass it
    back to ``run_bm25_search``. The index over the archive must build in
    under 15 seconds.
    """
    from cardinal_agent.pipelines.bm25 import BM25Index

    return BM25Index(docs)


def run_bm25_search(index: Any, query: str, k: int) -> list[tuple[int, float]]:
    """Problem (bm25).

    Return the top-k ``(doc_id, score)`` pairs for ``query`` as
    ``(int, float)`` tuples, best first, ties broken by lower doc_id (the
    document's position in the ``docs`` list given to ``run_bm25_build``).

    Rules the tests check:
    * Scores follow the BM25 scoring formula (k1 = 1.5, b = 0.75, Lucene IDF)
      to within 1e-6. The query is tokenized like the documents, and a term
      repeated in the query counts once.
    * A document that shares no term with the query is never returned, so
      the list may be shorter than k. A query with no tokens, or whose terms
      occur in no document, returns [].
    * A search reads only the index entries of the query's terms: 20 ms per
      query on average over the archive, and 2 ms for a term that occurs in
      3 of 200,000 documents.
    """
    return index.search(query, k)
```

## 8. 手写参考与局限

建议先用上面的三篇小文档，手写出 Counter、postings 和 doc_lengths；确认每个词的倒排记录无误后再加入公式，最后加入 top-k。不要先把整个公式和建索引逻辑混写在一起。公式测试通过后，再用真实档案检查性能。

BM25 不理解同义词，不直接推理事实，也不会自动处理政策新旧；高分代表关键词统计上的相关性，不保证答案正确。课程分词器不做词干还原或停用词过滤，因此严格沿用它以保持评分一致。所有词的 postings 都驻留内存；对于更大的语料需要其他存储方案，但本作业无需增加复杂度。

检索失败时要区分：关键词没有匹配上，还是匹配到了但排名不够高。前者可以在后续问答中改写查询，后者可检查稀有程度、词频和长度调整。不能通过硬编码公开问题及答案来改善召回。
